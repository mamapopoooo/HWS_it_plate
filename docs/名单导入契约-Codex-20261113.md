## 输入与列语义

沿用 POST /api/v3/roster/import 的 {rows,dryRun}，studentNo为字符串定位键，保留前导零，不在导入中改学号。
可更新列：name、nameEn、gender、class、course；grade由有效显式编辑或班级/课程推导，不增加表格猜测值。

| 输入 | 既有学生 | 新学生 |
|---|---|---|
| 键缺席或undefined | 保留原值，skipFields | 可选列默认；姓名/班级等必要资料不足则reject |
| 键存在但null/去空白后空字符串 | 保留原值，skipFields并warning，不能隐式清空 | 可选列默认；必要列reject |
| 键存在且有效 | writeFields；同步users对应档案，绝不改余额 | 用有效值新增，不写grade=0或无效class_id |
| 重复学号/类型错误/无效班级或年级 | reject，写明原因，不靠数据库500说明问题 | 同左 |

故意清空可选列仍走单条编辑。前端用表头映射决定键存在性，不能给未出现列预填空值。只在新记录必要字段不足时报错，不拒绝现有记录“学号+姓名”简表。
若同批包含重复studentNo，重复行均reject；不得隐式后行覆盖前行。普通逐行无效以rejected报告，所有可写有效行在事务提交；数据库意外失败须整批回滚并返回错误，不可把部分未提交行计入成功。

## 追加响应（保持旧字段）

dryRun保留dryRun/total/wouldCreate/wouldUpdate/invalid/garbled/existingNos；commit保留success/created/updated/rejected。
二者都追加rowPlans；已在src/api/roster.ts导出RosterImportPlan类型并经adapter转出。

```json
{
  "studentNo": "0001",
  "action": "update",
  "writeFields": ["name"],
  "skipFields": ["nameEn", "gender", "class", "course"],
  "warnings": ["英文名列为空，本次保留原值"],
  "errors": []
}
```

action只允许create/update/reject；writeFields/skipFields使用上述五个字段code。warnings与errors为中文字符串数组，不能泄露其他学生资料。
dryRun与commit使用同一计划函数，每次读取最新库重算；预演不写class/users，不保证并发期间快照锁定。若提交时计划与预演不同，页面必须显示新结果，不冒充原预演已执行。
旧响应没有rowPlans时，页面显示“详细预演尚不支持”，不得自行拼计划并当服务端确认。所有字段为兼容追加，不删除旧返回项。
