## 0. 一句话

**游戏的一切内容都是数据行，代码只负责读数据。** 加一只宠物、办一个活动、上一套皮肤、开一个新赛季，都应该是"插几行配置 + 传几张图"，不需要改任何代码、不需要动任何表结构。

---

## 1. 六条设计原则（先定原则，再定表）

| 编号 | 原则 | 具体含义 | 违反后的症状 |
|---|---|---|---|
| **P1** | **内容即数据** | 宠物、技能、皮肤、活动、任务、成就、赛季、排行榜、品阶、属性全部来自数据库/配置，代码里不出现具体内容 | 加一只宠物要改 5 个文件 |
| **P2** | **枚举集中** | 品阶、八卦、形态、经济参数只在一处定义，其他地方引用 | 改一个价格要全局搜索 |
| **P3** | **只加不删** | 数据库迁移只允许 `CREATE TABLE` / `ADD COLUMN`；字段废弃写注释，不 `DROP`；API 只做加法 | 老存档/老客户端崩掉 |
| **P4** | **前端不硬编码** | 界面文案（"四象""万象"）、图鉴分卷数、外框样式全部来自配置接口 | 加第六阶要改图鉴代码 |
| **P5** | **玩法插件化** | 任务/成就/活动用 `condition_json` + `reward_json` 描述；新增**类型**才写 handler | 每加一个成就写一段 if-else |
| **P6** | **YAGNI** | 只预留**扩展点**，不预建空表；不确定的东西加字段注释就够 | 表越建越多，没人敢动 |

> P1 和 P6 看似矛盾，边界是：**扩展点要留够（字段/JSON/配置表），但不为想象中的玩法建实体表。**

## 2. 分层架构

```
┌─ 配置层 config ────────────────────────────────────────┐
│ tier_config      五阶（可扩展第 N 阶）                   │
│ trigram_config   八卦（可扩展变异属性）                  │
│ form_config      形态解锁条件                           │
│ economy_config   价格/概率/倍率（全部可调）              │
└───────────────────────┬────────────────────────────────┘
┌─ 内容层 content ──────┴────────────────────────────────┐
│ pets_template   宠物（含 tier/trigram/form_images JSON） │
│ skill_effects   技能效果池（cost + 参数字段）            │
│ skills          官方技能（引用 skill_effects）           │
│ skins           角色皮肤                                │
│ events          活动（cond_json/reward_json）           │
│ quests          任务                                    │
│ achievements    成就                                    │
│ seasons         赛季                                    │
│ ranking_config  排行榜榜种                              │
└───────────────────────┬────────────────────────────────┘
┌─ 玩家层 player ───────┴────────────────────────────────┐
│ users / characters / player_pets / player_skills        │
│ player_items / player_quests / player_achievements      │
│ custom_pets / custom_pet_skills   ← 无极造物             │
└───────────────────────┬────────────────────────────────┘
┌─ 记录层 log ──────────┴────────────────────────────────┐
│ points_records / gacha_records / battle_records         │
│ exchange_records / audit_logs / schema_migrations       │
└─────────────────────────────────────────────────────────┘
```

**依赖方向只能向下**：内容层不引用玩家层，代码不反向依赖具体内容。

## 3. 配置层（改这些 = 调游戏规则）

### 3.1 `tier_config`

| 字段 | 类型 | 说明 |
|---|---|---|
| `tier` | INTEGER PK | 1–5（**数字，排序友好**） |
| `code` | TEXT | `wanxiang` / `bagua` / `sixiang` / `taiji` / `wuji` |
| `name` | TEXT | 万象 / 八卦 / 四象 / 太极 / 无极 |
| `subtitle` | TEXT | 山海异兽 / 八属之灵 / 四方神兽 / 阴阳之鱼 / 造物 |
| `power_coef` | REAL | 1.00 / 1.12 / 1.25 / 1.40 / 1.57 |
| `form_count` | INTEGER | 2 / 3 / 4 / 5 / 6 |
| `awaken_cap` | INTEGER | 1 / 2 / 3 / 4 / 5（= form_count − 1） |
| `skill_slots` | INTEGER | 2 / 3 / 4 / 5 / 6 |
| `gacha_rate` | REAL | 0.70 / 0.22 / 0.065 / 0.015 / 0（不进池） |
| `bezel_color` | TEXT | 外框主色（前端读，不写死） |
| `is_gacha` | BOOLEAN | 是否进抽卡池 |

> **加第六阶「混元」** = 插一行 + 给外框色 → 图鉴自动多一卷、抽卡自动参与、觉醒上限自动生效。**0 行代码。**

### 3.2 `trigram_config`

| 字段 | 说明 |
|---|---|
| `code` | `qian` / `kun` / `zhen` / `xun` / `kan` / `li` / `gen` / `dui` |
| `name` / `symbol` | 乾 / ☰ |
| `element` | 天 / 地 / 雷 / 风 / 水 / 火 / 山 / 泽 |
| `color` / `color_dark` | 石青 / 深色描边 |
| `opposite` | 对宫 code（克制用） |
| `sort_order` | 显示顺序（先天八卦序） |

克制关系由 `opposite` **自动推导**，不在代码里写四对常量：

```js
// 对宫互指（乾↔坤…），所以相冲必然是双向的：只有 1.3 或 1.0，没有单向减伤
const coef = (atk, def) => (cfg[atk].opposite === def ? 1.3 : 1.0)
```

> **为什么没有 ×0.77 的「被克」**：先后两版设计都写过 1.3 / 0.77，但 `opposite` 是互指的，
> `cfg[def].opposite === atk` 与 `cfg[atk].opposite === def` 恒等价 —— 0.77 那条分支永远走不到。
> 2026-11-03 由单测（`src/config/gameConfig.test.ts`）发现并修正：**对宫互相都是 1.3**，不做减伤。
> 若以后真需要攻防差异，应给属性加 `beats` 单向表，而不是复用 `opposite`。

> **加第九个属性** = 插一行 + 指定 `opposite` → 克制表自动生效。

### 3.3 `form_config`

| 字段 | 说明 |
|---|---|
| `tier` | 所属品阶 |
| `form` | 1..N |
| `unlock_awaken` | 解锁所需觉醒阶（默认 form−1） |
| `form_name` | 初相 / 化相 / 法相 / 真形 / … |
| `aura_level` | 光效强度 0–5（前端映射到 CSS 变量） |

> 形态数与解锁条件**解耦**：以后想让某个品阶多一形态，只加一行。

## 4. 内容层

### 4.1 `pets_template`（宠物模板）

```sql
CREATE TABLE pets_template (
  id            TEXT PRIMARY KEY,          -- pet_jiuweihu
  name          TEXT NOT NULL,             -- 九尾狐
  tier          INTEGER NOT NULL DEFAULT 1,
  trigram       TEXT,                      -- 主属性 code；四象可 "zhen,xun"
  source        TEXT,                      -- 出处：南山经（文化属性，详情页展示）
  description   TEXT,
  form_images   TEXT,                      -- JSON {"1":"...","2":"..."}（不写死 3 列）
  base_stats    TEXT,                      -- JSON {hp,atk,def,spd}
  skills_json   TEXT,                      -- JSON ["skill_jiuweihu_1", ...]
  unlock_cond   TEXT,                      -- JSON；隐藏/活动限定用
  is_active     INTEGER DEFAULT 1,
  is_custom     INTEGER DEFAULT 0,          -- 1 = 学生造物（无极）
  sort_order    INTEGER DEFAULT 0,
  created_at    INTEGER, updated_at INTEGER
);
```

> **加一只万象**：插一行 + 传 2 张图 → 图鉴自动进「万象」卷、抽卡池自动包含、详情页自动可看。**0 行代码。**

### 4.2 技能

```sql
-- 效果池（数值由系统给，学生只能选，不能填）
CREATE TABLE skill_effects (
  code TEXT PRIMARY KEY,      -- damage_single / heal_pct / shield_pct / buff_atk / stun / first_strike
  name TEXT, cost INTEGER,    -- 灵力消耗
  params_json TEXT,           -- {"power":{"min":60,"max":120,"step":10}}
  impl TEXT,                  -- handler 标识，新增效果类型才需要写代码
  is_active INTEGER DEFAULT 1
);

-- 官方技能 + 学生技能共用一张表
CREATE TABLE skills (
  id TEXT PRIMARY KEY,        -- skill_jiuweihu_1 / custom_u42_1
  owner_pet_id TEXT,          -- 官方技能挂模板；学生技能挂 custom_pet
  name TEXT, description TEXT,
  effect_code TEXT,           -- 引用 skill_effects
  params_json TEXT,           -- {"power":100,"extra":{"burn":2}}
  cooldown INTEGER DEFAULT 0,
  is_custom INTEGER DEFAULT 0,
  status TEXT DEFAULT 'active' -- active / pending / rejected
);
```

> **加一个新效果类型**（如"吸血"）= 插 `skill_effects` 一行 + 写一个 `impl` handler（这是唯一允许写代码的扩展）。

### 4.3 角色与皮肤

```sql
CREATE TABLE characters (            -- 玩家角色（每人一个）
  id TEXT PRIMARY KEY,               -- char_<userId>
  user_id TEXT UNIQUE NOT NULL,
  gender TEXT DEFAULT 'female',      -- male / female
  nickname TEXT,                     -- 昵称（可改，15 分）
  skin_id TEXT DEFAULT 'skin_base',  -- 当前穿戴
  avatar_pose TEXT DEFAULT 'stand',  -- 预留：站/坐/战
  created_at INTEGER, updated_at INTEGER
);

CREATE TABLE skins (
  id TEXT PRIMARY KEY,               -- skin_base_m / skin_hanfu_f
  name TEXT, theme TEXT,             -- base / hanfu / season / graduate
  gender TEXT,                       -- male / female
  price INTEGER DEFAULT 0,           -- 0 = 免费
  image TEXT,                        -- 1024×1536 全身立绘
  unlock_cond TEXT,                  -- JSON；毕业纪念等
  is_active INTEGER DEFAULT 1,
  sort_order INTEGER DEFAULT 0
);

CREATE TABLE player_skins (
  user_id TEXT, skin_id TEXT, obtained_at INTEGER,
  PRIMARY KEY (user_id, skin_id)
);
```

> **加一套皮肤** = 插 2 行（男/女）+ 传 2 张图。**0 行代码。**
> 宠物皮肤表 `pet_skins` **停用**（P3：不删，保留空表 + 注释）。

### 4.4 活动 / 任务 / 成就 / 赛季 / 榜种

```sql
CREATE TABLE events (
  id TEXT PRIMARY KEY,               -- event_2026s1_midautumn
  name TEXT, type TEXT,              -- gift / double_points / limited_draw / festival
  start_at INTEGER, end_at INTEGER,
  cond_json TEXT,                    -- {"all":[{"type":"collect_tier","tier":3}]}
  reward_json TEXT,                  -- [{"item":"points","amount":30},{"item":"pet","id":"pet_bixie"}]
  limit_json TEXT,                   -- {"perUser":1}
  banner_image TEXT,
  is_active INTEGER DEFAULT 1
);

CREATE TABLE quests (      /* 已有，增加 type/cond_json/reward_json/refresh */
  id TEXT PRIMARY KEY, name TEXT, type TEXT,        -- daily / weekly / season
  cond_json TEXT, reward_json TEXT, is_active INTEGER DEFAULT 1, sort_order INTEGER DEFAULT 0
);

CREATE TABLE achievements ( /* 同上，加 cond_json */
  id TEXT PRIMARY KEY, name TEXT, category TEXT, cond_json TEXT,
  reward_json TEXT, is_active INTEGER DEFAULT 1
);

CREATE TABLE ranking_config (
  id TEXT PRIMARY KEY,               -- points / power / collection
  name TEXT, metric TEXT,            -- 取值表达式：points / power / collection_rate
  scope TEXT DEFAULT 'grade',        -- grade / class / all
  reset_cycle TEXT DEFAULT 'season',
  top_pose INTEGER DEFAULT 7,        -- 前台 7 名出立绘
  is_active INTEGER DEFAULT 1
);
```

> **办一个活动** = 插 `events` 一行 + 传横图。**0 行代码。**
> **加一个榜** = 插 `ranking_config` 一行（`metric` 是已有字段表达式）。**0 行代码。**

## 6. 规则与数值（当前生效值）

### 6.1 品阶

| tier | 名称 | 数量 | 形态 | 觉醒上限 | 技能 | 战力系数 | 抽卡率 |
|---|---|---|---|---|---|---|---|
| 1 | 万象 | 24 | 2 | 1 | 2 | 1.00 | 70% |
| 2 | 八卦 | 8 | 3 | 2 | 3 | 1.12 | 22% |
| 3 | 四象 | 4 | 4 | 3 | 4 | 1.25 | 6.5% |
| 4 | 太极（阴阳鱼） | 2 | 5 | 4 | 5 | 1.40 | 1.5% |
| 5 | 无极（造物） | 每人 1 | 6 | 5 | 6 | 1.57 | 0% |

**图鉴 = 38 只官方 + 每人 1 只本命（无极）**。美术总量：万象 48 + 八卦 24 + 四象 16 + 太极 10 = **98 张**（无极不出图，用学生上传）。

### 6.2 属性与克制

八属性走 `trigram_config.opposite`：乾↔坤、震↔巽、坎↔离、艮↔兑。**对宫互冲 ×1.3，其余 ×1.0（相冲双向，无单向减伤）**。
四象双属性（青龙=震+巽、白虎=乾+兑、朱雀=离、玄武=坎，防御取最优）；太极全属性、不吃克制。

### 6.3 等级 / 觉醒 / 战力

```
属性 = 基础属性 × 品阶系数 × (1 + 0.05 × (等级 − 1)) × (1 + 觉醒加成)
觉醒加成 = [0, 10%, 25%, 50%, 100%, 150%]     // 0–5 阶，按品阶封顶
战力 = round(100 × 品阶系数 × 等级系数 × (1 + 觉醒加成))
```

示例：四象 Lv.7 觉醒 3 → 244；无极 Lv.7 觉醒 5 → 510。

### 6.4 经济（单一货币：积分）

| 类目 | 价格 |
|---|---|
| 单抽 / 十连 | 5 / 45 |
| 保底 | 20 抽内必出八卦+，60 抽内必出四象+；太极无保底（活动为主） |
| 兑换 | 万象 250 / 八卦 450 / 四象 800 / 阴阳鱼 900 / **无极易不可兑换** |
| 觉醒 | 30 / 50×2 / 80×3 / 120×4 / 160×5 |
| 角色皮肤 | 校服 60 / 汉服 120 / 赛季 150 / 毕业纪念免费 |
| 小额 | 称号 40 / 改名 15 / 换卦象 50 / 补斗法 3 |
| 重复转碎片 | 20 / 60 / 200 / 500（碎片最多抵 50% 觉醒费） |
| **年级系数** | **G6 = 1.0，G7 = 0.6**（G7 只有一年课程，总量子约为 G6 的 1/4） |

预期：G6 两年 ≈ 240 抽 → 全图鉴差 1 条鱼；G7 一年 ≈ 100 抽 → 万象全 + 八卦全 + 四象 3。

## 8. 无极造物（UGC）

### 8.1 解锁

集齐 **阴鱼 + 阳鱼** → 解锁「造物」功能（不自动发宠物，而是给**创作权**）。

### 8.2 形象三路径（统一产出 1024² 透明 PNG）

| 路径 | 说明 |
|---|---|
| 拼装 | 内置部件库（头/身/尾/角/翼/纹样/配色），最易用 |
| 手绘 | 上传 PNG（模板下载 + 规格校验） |
| AI 生成 | 用我们给的提示词模板出图后上传，需老师把关 |

### 8.3 技能：自由命名 + 效果池组合

- 灵力预算 **120 点**；
- 效果取自 `skill_effects`（每项有 cost），学生只选效果、填名字（≤6 字）与描述（≤40 字）；
- **不允许填数值** —— 这是防超模的硬约束。

### 8.4 审核流

```
提交 → 自动校验（尺寸/透明底/敏感词/灵力超限/数量）
     → 教师后台待审队列（预览立绘 + 技能表）
     → 通过 / 驳回（附理由，可重提，最多 3 次）
```
审核状态：`pending / approved / rejected`，全部写 `audit_logs`。

### 8.5 形态

无极的 6 个形态**不出新图**：同一张立绘 + 光效递进（法阵/金身/领域，纯 CSS）。这样 UGC 宠物只需 1 张图，两年级的学生都能"造完就能用"。

## 9. 排行榜

### 9.1 三个榜（配置驱动，见 `ranking_config`）

|---|---|---|---|
| 积分榜 | `points` | 按年级 | 赛季 |
| 战力榜 | `power` | 按年级 | 不重置 |
| 收集榜 | `collection_rate` | 按年级 | 不重置 |

### 9.2 展示分级

| 名次 | 展示 |
|---|---|
| 1–3 | **领奖台**：角色放大立绘（≥200px）+ 名次徽记 + 分数 |
| 4–7 | 角色**全身缩小图**（80px）+ 名字 + 分数 |
| 8+ | **只显示名字 + 分数**（无立绘，行高 40px） |

名字格式 **`昵称 · 姓名`**（例：`小狐仙 · 李四`）；自己那行高亮并吸底；全部公开可见。

## 11. 契约（三方对齐的格式）

### 11.1 DSL

```jsonc
// 条件
{"all":[{"type":"battle_win","value":3},{"type":"possess_tier","tier":3}]}
{"any":[{"type":"collect_count","value":20},{"type":"event_done","id":"event_2026s1"}]}

// 奖励
[{"item":"points","amount":30},{"item":"pet","id":"pet_dangkang"},{"item":"skin","id":"skin_hanfu_f"}]

// 技能效果参数
{"code":"damage_single","params":{"power":100,"extra":{"burn":2}}}
```

### 11.2 ID 规范

| 类型 | 格式 | 例 |
|---|---|---|
| 宠物 | `pet_{拼音}` | `pet_jiuweihu` |
| 官方技能 | `skill_{宠物}_{序号}` | `skill_jiuweihu_1` |
| 学生技能 | `custom_{userId 前 6}_{序号}` | `custom_u42ab1_1` |
| 品阶 | `tier_{数字}` | `tier_3` |
| 属性 | `trigram_{code}` | `trigram_qian` |
| 活动 | `event_{赛季}_{主题}` | `event_2026a_midautumn` |
| 皮肤 | `skin_{主题}_{性别}` | `skin_hanfu_f` |
| 成就/任务 | `ach_{code}` / `quest_{code}` | `ach_first_win` |

### 11.3 字段规范

- 所有内容表必须有：`is_active`、`sort_order`、`created_at`、`updated_at`；
- 所有 JSON 字段必须有默认 `'{}'` 或 `'[]'`，不得为 `NULL`；
- 所有时间用 **毫秒时间戳 INTEGER**（与现有库一致）。

## 16. 明确不做的事（防止过度设计）

| 不做 | 原因 |
|---|---|
| 预建好友/公会/交易表 | 两年内很可能用不上，且会拖慢每次迁移 |
| 多货币体系 | 老师要的是"加一次分"，副货币会被学生自动换算成麻烦 |
| 宠物皮肤 | 已整体迁移到角色端，避免两套装饰系统抢美术预算 |
| 无极进抽卡池 | 造物是毕业奖励，抽到就失去意义 |
| 跨年级同榜 | G6 每周 8 节、G7 每周 4 节，同榜对 G7 不公平 |
| 学生自由填技能数值 | 一周内就会出现"一击必杀"，效果池是硬约束 |
| 色情性化 / 血腥暴力 / 恐怖内脏内容 | 面向 11–14 岁学生，目标分级全年龄；红线与改写原则见 [`内容安全红线.md`](./内容安全红线.md) |
