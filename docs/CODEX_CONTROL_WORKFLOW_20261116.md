# CODEX-CONTROL：独立分数输出与反馈流程

日期：2026-11-16；状态：设计约束，未实现、未联调，生产上传关闭。

## 用户确认的范围

管控与平台仅对接分数输出。以独立导出器进程读取分数事件副本并管理自己的outbox、HTTP、重试和日志；平台不反向控制管控，不下发锁屏、名单或配置指令。原主程序的通信、锁定/解锁、白名单、考试、启动服务与部署行为不受此模块故障影响。

当前契约中的“主程序先保存outbox再更新UI”改为隔离约束：原管控记分成功不依赖平台或导出器确认。优先只读消费已有持久记分日志；若原系统没有可靠事件源，先提交最小本地事件出口方案供审核，不擅改主程序。网络、持久重试和平台凭据不得进入UI回调或原服务启动关键路径。

独立进程不自动保证零影响：限定CPU/内存/磁盘占用，限制日志轮转及重试；使用独立目录、配置、数据库与进程，禁止写原管控数据库、抢占锁或启动时扫描全量历史分数。导出器不存在、崩溃、磁盘异常、平台断网时，原功能继续可用。事件缺口明确报待核对，不能为了可用性伪称可靠送达。

学号唯一，缺映射不猜测。持久eventId/lessonId重试不变；只发送增量，不发送余额覆盖，不回灌平台消费。累计分与消费余额分别记账；负分及撤销按平台确认契约执行。既有事件ID不因模块重启重新生成。

能力探测、服务端幂等事务、逐条ACK未验收前上传关闭；不用真实POST试探。测试采用虚构学生和隔离服务，验证导出器停用/崩溃/超时不影响原管控、离线重启恢复、丢响应不重复记账、资源上限和磁盘故障。

## 本角色反馈流程

身份固定CODEX-CONTROL；平台技术整合Codex为审核者。本人只维护CODEX_CONTROL_*文档和自己的REPORT/交接单，不代写FEEDBACK。

每次读取整合分支本人FEEDBACK，记录绝对工作区、任务分支、基线及补丁SHA。按CC编号汇报问题、文件、实现范围、脱敏证据、实际测试结果、未验证项及平台依赖。状态依次为待审、需修改/需决定、修复待复验、复验通过；提交不等于验收，验收不等于生产启用。
