## 现行整合决定

经济默认值仍唯一来自docs/seeds/economy.json；运行期economy_config按键覆盖默认。G6=1、G7=0.6，不把倍率写死在路由；无效负价/倍率拒绝。正价按Math.round且至少1，明确免费商品保持0。
道具先取整单价再乘正整数数量，拒绝0/负数/小数/字符串数量及超出安全整数的总价。皮肤价格只算一次，余额判定/扣款/回执使用同一值。

| 路由 | 行为 |
|---|---|
| /api/v2/shop/buy | 数据库道具基价，经配置换算；扣款/资产/兑换流水同事务 |
| /api/v2/shop/skins/buy、/api/v3/character/buy-skin | 兼容原有两种皮肤表；免费0、重复购买拒绝，事务扣款发货 |
| /api/v2/pets/:petId/awaken、/api/v3/pets/:petId/awaken | 共享品阶费用、觉醒上限、awakeningPayment碎片抵扣；不再用旧500递增公式，旧响应字段保留并追加明细 |
| /api/v2/gacha/draw {kind}、/api/v3/gacha/draw {count} | 正式池共用KIMI已验证drawMany、20/60保底，太极不额外保底；G7单抽3、十连27 |
| /api/v2/gacha/draw {eggType,count} | 兼容旧蛋池；旧基价200/500/1000移入legacyGacha配置，未改旧概率/保底；G7同样0.6 |

正式求签同时保持camelCase旧返回与pet_id/is_new/fragments字段；pity按(user_id,egg_type='v3')隔离，不覆写旧蛋型计数。抽取、保底、宠物/碎片、流水与条件扣款同事务，任何写入失败整批回滚。
v2/v3共用觉醒会同时扣碎片和积分，返回totalCost/fragmentCost/cost与新形态。正价公式/碎片比例均读配置，不重置玩家余额。
