# 学生身份只读盘点与后续处理

状态：工具已完成虚构临时库测试；没有访问真实名单或生产库，没有迁移身份或合并资产。

## 使用边界

在本人独立工作区使用已安装本项目better-sqlite3预编译包的Node版本（本轮Node22）。只对授权的本地一致性SQLite快照操作：

```powershell
node scripts/audit-student-identities.mjs --db 'D:\本人的测试目录\snapshot.db'
```

必须显式传--db，不读取PET_GARDEN_DB，不默认打开server/pet-garden.db。文件不存在直接失败，不会创建数据库；缺字段不会执行initDb或迁移。
用readonly/fileMustExist及query_only打开文件，在同一读事务内取得名册和身份。只读students.student_no及users.username/role/is_guest，不读姓名、密码、积分或宠物数据。
应使用服务已关闭或通过SQLite备份方式生成的一致性快照，不用单独复制在线WAL库的.db文件；获取生产快照仍受现有冻结约束，本工具不负责远程连接或备份生产。

## 输出与退出码

输出仅有assessment和聚合计数，无姓名、学号、用户ID、数据库路径或资产明细。

- canonicalOnly：名单只有裸学号学生身份；本轮登录沿用原id。
- legacyOnly：只有stu_旧身份；当前登录409，不自动新建第二条用户。
- dualIdentities：裸学号与旧前缀并存；不合并资产，待人工方案。
- accountCollisions：相关用户名重复，或被非学生/游客身份占用。
- duplicateRosterGroups/invalidStudentNumbers/untrimmedStudentNumbers：重复、空或非字符串、首尾空白学号待清理。
- ambiguousAccountLinks：某用户名同时可能对应一个学生的裸学号和另一学生的旧前缀，禁止自动归并。
- rosterPrefixCollisions：名单中同时存在X和stu_X，尚未创建身份也需人工核对；共享登录已阻断stu_X一侧自动认领或建号，防止继承X的旧账号资产。
- orphanStudentUsers：非游客学生身份无法通过当前裸学号或旧前缀映射到名册；不按姓名猜归属。
- missingIdentity：名册尚未创建用户；这可以是正常首次登录前状态，不单独当作资产冲突。

退出0：未发现上述冲突；不等于认证或全系统验收通过。
退出2：盘点完成，存在需复核项；退出1：参数/库/字段等原因导致盘点未完成。
类别统计针对不同对象，不可把所有计数简单相加当作人数。复核项无自动修复开关。
