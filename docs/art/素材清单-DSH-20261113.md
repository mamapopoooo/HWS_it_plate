## 三、路径与命名（必须严格一致，否则前端读不到）

前端读图规则（`src/config/gameConfig.ts: formImage`）：

```
/pet-garden/pets/{去掉 pet_ 前缀的 id}/form{形态号}.png
/pet-garden/characters/{skin_id 去掉 skin_ 前缀}.png
```

对应仓库路径：

```
public/pets/qinglong/form1.png
public/characters/base_m.png
```

若某只宠物有特殊形态图，可在 `pets.json` 用 `formImages` 覆盖，但**默认必须遵守上面的约定**。

## 四、规格与验收（每条都要过）

| 项 | 要求 |
|---|---|
| 格式 | **PNG-24 真透明**（不是白底、不是淡紫底） |
| 体积 | 宠物单张 ≤250KB（原图另存，交付压缩版） |
| 描边 | 闭合、6–10px，暗底上能立住 |
| 明度 | ≥45%，暗部同色压暗，不要脏灰 |
| 64px 可辨 | 缩到 64px 仍能认出是哪只 |
| 多形态一致 | 同宠物的脸/配色/标志性特征必须一致（后续 form2–4 依此） |
| 内容 | 无血、无伤、无骷髅、无恐怖、无性化、无水印、无文字 |
| 风格 | 严格对位：俊逸（青龙/白虎）、雅致（朱雀）、奇诡（玄武） |

> 玄武是"奇诡"，但**奇在结构（多首/异肢），不奇在恶心**。

## 六、交付方式

1. 图片放到上述路径（或给可下载文件，由 DSH 接入）；
2. 在 `docs/art/` 下写交付说明：实际尺寸、alpha 是否真透明、体积、未达标项；
3. 交付后 DSH 跑 `node scripts/check-art.mjs` + 页面实看（暗底、64px、切形态、缺图回退）。

**不要在没确认风格前批量出图** —— 第一批 6 张定稿后，再按品阶分批补齐剩余 92 张。
