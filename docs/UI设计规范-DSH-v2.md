## 1. 觉醒三形态体系

### 1.1 形态与觉醒阶的映射（推荐方案）

觉醒阶仍是 **0–4（5 档）**，保持与现有后端 `awakening_level` 和数值加成表（+0%/+10%/+25%/+50%/+100%）一致；但**立绘只在 3 个点上换图**：

| 觉醒阶 | 形态 | 立绘 | CSS 叠加层 |
|---|---|---|---|
| 0 | 初始 form1 | 图 1 | 无 |
| 1 | 初始·觉醒 | 图 1 | 金环 I + 呼吸 |
| 2 | **共鸣 form2** | **图 2（换图）** | 金环 II + 6 粒子 |
| 3 | 共鸣·爆发 | 图 2 | 旋转锥光 + 12 粒子 + 星芒 |
| 4 | **究极 form3** | **图 3（换图）** | 双环反向 + 24 粒子 + 环境光 |

> 好处：数值不用改、数据库不用改、UI 只需在 `awakeningLevel === 2` 与 `=== 4` 时换 `src`。缺点是 5 档里只有 2 次换图 —— 如果你想让「每一阶都肉眼可见地长个」，就得 5 张图（见 §7 Q3）。

**换图过渡动效（关键，决定「刺激感」）**：不是 `src` 直接跳，而是：

```
0ms    旧图 opacity 1 → 0（200ms），同时整体过曝 flash：位移 0 / 亮度 +60%
200ms  新图 opacity 0 → 1（400ms），从 scale(0.92) 弹到 1（--e-back）
300ms  白色扩散光环 0 → 420px 淡出（600ms）
400ms  新形态台词条从底部弹入（"共鸣形态 · 觉醒了！"）
```

### 1.2 三形态的差异设计语言（美术要遵守的规则）

同一只宠物，三个形态必须在**四个维度**上递进，否则学生看不出"变强了"：

| 维度 | 初始 | 共鸣 | 究极 |
|---|---|---|---|
| 体型 | 100% | **112–115%** | **130–135%** |
| 轮廓配件 | 无 | +1 处（披风 / 尾焰 / 肩甲 / 鬃毛） | +3 处以上（翼 / 冠 / 飘带 / 浮空环） |
| 配色 | 原色 | 主色不变 + 饱和度 +12% + 出现第二强调色 | 主色保留 60% + 金/紫金属色 + 内部发光纹路 |
| 光 | 无 | 体表出现微光缝隙 | **自身发光**（不是外圈光，是身体里的光） |

### 1.3 现有素材盘点（重要）

仓库里 **26 只宠物 × 7 级图**（`public/pets/{id}/lv1..lv7.png`）其实已经是三段式进化链，比如老虎：

| 文件 | 内容 | 可对应形态 |
|---|---|---|
| `tiger/lv1.png` | 趴着的幼崽 | **初始** |
| `tiger/lv4.png` | 肌肉壮虎，金瞳 | **共鸣** |
| `tiger/lv7.png` | 星空神虎，光环 + 飘带 | **究极** |

**所以有三种做法（§7 Q1 请你选）：**

- **A｜复用**：初始=`lv1`、共鸣=`lv4`、究极=`lv7`，零新增美术成本，今天就能上线；
- **B｜全新出图**：每只宠物再画 3 张专用觉醒立绘（26×3 = 78 张）；
- **C｜混合（我推荐）**：**6 只对战宠物**（焰尾狐等）出专属三形态（18 张），**20 只养成宠物**复用等级图。

### 1.4 现有图的三个硬伤（必须处理）

| 问题 | 现状 | 解决 |
|---|---|---|
| 背景 | 1024×1024 **JPEG**，淡紫平底 `#E5DFF0` | 出图改 **PNG-24 透明底**；过渡期用 CSS 蒙版 + 光台遮掉方角（预览稿已这么做） |
| 水印 | 右下角「Qoder AI 生成」 | 重新出图时在提示词里禁文字/水印；已存在的图裁掉 12% 右/下边 |
| 比例 | 主体占画布比例不一（幼崽偏小、神虎撑满） | 统一「主体高 72%、底边留 8%」，否则换图时宠物会突然变大变小 |

## 2. 美术生产规范（投喂绘图 AI 用）

### 2.1 输出规格

| 项 | 要求 |
|---|---|
| 尺寸 | 1024×1024（1:1），后续可直接 4 档导出（512/384/256/128） |
| 格式 | **PNG-24 透明背景**；单张 ≤ 250KB；可选 WebP 回退 |
| 构图 | 正面或微 3/4，全身，双眼可见，主体高占画布 **72%**，底边留 **8%** |
| 描边 | 6–8px 闭合粗描边（1024 画布），便于抠图与暗底辨识 |
| 光照 | 左上 45° 主光 + 背后同属性色轮廓光；眼睛必须高光 |
| 禁止 | 文字 / 水印 / 边框 / 地面投影 / 多主体 / 场景背景 |

### 2.2 命名与目录

```
public/pets/{petId}/
├── lv1.png … lv7.png      # 现有等级图，不动
├── form1.png              # 初始形态（若复用 lv1，则不必新建）
├── form2.png              # 共鸣形态
└── form3.png              # 究极形态
```

前端取图统一走 `getPetFormImage(petId, form)`，内部按 §1.3 选 A/B/C 策略回落：`form{N}.png → 策略映射的 lv 图 → lv1.png`。

### 2.3 提示词模板（三形态通用骨架）

```
主体：{宠物名}，{外观描述：毛色 / 特征 / 尾巴}，正面站立全身像，
      游戏立绘风格，赛璐璐平涂 + 柔和渐变阴影，干净闭合粗描边，眼睛有高光。
形态：{初始 | 共鸣 | 究极}形态 —— {本形态差异描述}
背景：纯透明背景（PNG），无场景、无地面、无文字、无水印、无边框。
构图：主体高度占画布 72%，底部留 8% 空间，居中。
风格：赛尔号 / 宝可梦式少年向游戏立绘，色彩饱和但不过曝。
```

### 2.4 焰尾狐三形态示例（可直接用）

| 形态 | 差异描述（填进 `{本形态差异描述}`） |
|---|---|
| 初始 | 小体型狐狸幼崽，耳朵大，尾巴末梢一簇小火苗，琥珀色眼瞳，无额纹 |
| 共鸣 | 体型放大 15%，肩颈处浮现半透明火焰披风，尾巴分裂成三簇火苗，胸口出现金色火纹，眼神锐利 |
| 究极 | 体型放大 35%，九条火焰尾呈扇形展开，额心金色焰冠，周身漂浮火羽，脚下环绕熔岩光环，眼瞳呈熔金色 |

### 2.5 验收清单（每张图过一遍）

- [ ] 透明背景，无方角、无水印、无文字
- [ ] 主体高度 72%、底边留 8%，与同组另两形态基线对齐
- [ ] 同一宠物三形态的**面部特征一致**（能认出是同一只）
- [ ] 脉动检查：三张图快速切换时，只有"变大变华丽"，不能"变成另一只宠物"
- [ ] 深色背景（`#0A0E1A`）下边缘无白边/黑边（抠图毛刺）

## 3. 主界面：赛尔号式游戏大厅

### 3.1 布局分区（1280×720 基准）

```
┌──────────────────────────────────────────────────────────────┐

│ 功能坞  │        精灵站台（中央视觉焦点）      │  任务面板 w=300   │
│ w=96   │                                  │ ┌──────────────┐ │
│ ⚔战斗  │      ✦ 三形态切换 tab ✦          │ │每日任务 3/4   │ │
│ 🐾宠物  │                                  │ │ ▸ 登录 +5    │ │

│ 📖图鉴  │      ╲   旋转台座    ╱            │ ┌──────────────┐ │
│        │        ╰──────────╯              │ │公告 / 赛季信息 │ │
│        │     ╭────────────────╮            │ └──────────────┘ │
│        │     │ 焰尾狐 · 究极形态 │  ← 名称牌（斜切金字）       │
│        │     │ ★★★★★★ 火      │            │                  │
├────────┴──────────────────────────────────┴──────────────────┤
│ CTA  h=88   [⚔ 开始战斗]   [🐣 抽卡 10 连]   [🏆 排行榜]        │
└──────────────────────────────────────────────────────────────┘
```

- **中央精灵台**是唯一视觉焦点：精灵立绘 + 三层旋转光环 + 底部台座 + 向上光柱 + 漂浮粒子
- 右面板可折叠（`w=300 → 48` 只留图标），给宽屏留空间
- 功能区不用文字列表，用**图标 + 短标签**的方形/圆形按钮

### 3.2 色板（相对 v1 的调整）

| 令牌 | v1 | v2 | 说明 |
|---|---|---|---|
| 页面底 | `#f5f7fa`（浅） | **`#0A0E1A → #16112B` 深空渐变** | 游戏感的基础 |
| 星云 | — | `#3B1A63` / `#0E3B5C` | 两层 radial，`blur(60px)` |
| 面板 | 白 + 灰边 | `rgba(15,23,42,.93)` + `1px rgba(125,211,252,.35)` | 半透明深色 + 科技描边 |
| 高稀有描边 | — | `#FFD700`（金）/`#C084FC`（紫） | 6★ 用金 |
| 文字 | `#1f2937` | 主 `#F8FAFC` / 次 `#94A3B8` | 深底反色 |
| CTA | primary 橙 | `#FF9F43 → #FF7A1A` 渐变 + 内高光 | 底部主按钮 |
| 成功/危险 | 沿用 | `#26DE81` / `#EF4444`（深底上提亮一档） | 对比度 ≥4.5:1 |

### 3.3 面板与按钮的"游戏化"处理

| 手法 | 实现 | 用在哪 |
|---|---|---|
| 斜切角 | `clip-path: polygon(0 12px, 12px 0, ...)` | HUD、面板、名称牌 |
| 双层描边 | 外层渐变底 + 内层 2px 深色 inset | 名称牌、稀有卡 |
| 内高光 | `box-shadow: inset 0 1px 0 rgba(255,255,255,.18)` | 所有按钮（立体感来源） |
| 扫光 | `linear-gradient` 115° 平移，2.6s 循环 | CTA、6★ 卡 |
| 呼吸发光 | `box-shadow` 透明度 0.35↔0.6，2.4s | 当前选中的功能按钮 |
| 悬浮 | `translateY(-6px)`，3.2s 正弦 | 精灵立绘 |

### 3.4 动效清单

| 元素 | 动画 | 周期 |
|---|---|---|
| 星点 | 透明度 0.2 ↔ 1 随机错峰 | 2–5s |
| 精灵立绘 | 上下漂浮 ±8px | 3.2s |
| 台座光环 | 顺时针旋转 | 12s |
| 光柱 | 透明度呼吸 | 2.4s |
| 粒子 | 上升 + 淡出，10–24 个 | 2.2s |
| CTA 扫光 | 左→右扫过 | 2.8s |
| 形态切换 | 过曝 flash + 新图弹入（§1.1） | 900ms |

### 3.5 移动端（<900px）

- 左右侧栏收起：功能坞变**底部 5 图标横排**，任务面板变右上角浮动按钮 → 抽屉
- 精灵台上移，占约 58vh；名称牌贴底部
- CTA 变全宽双按钮（战斗 / 抽卡），高 56px
- 所有可点区域 ≥ 44×44px

### 3.6 教师端怎么办

教室投影场景下，教师端要的是「快速找到学生 → 点一下加分」，游戏大厅会拖慢效率。建议：

- **学生端** = 游戏大厅（本规范）
- **教师端** = 保留现有卡片网格布局，只换深色外壳（同一套令牌）+ 顶部加 HUD（班级/人数/今日加分），**不做**精灵台
- 两边共用 `tokens.css`，教师端只是「暗色皮肤」，不改信息密度

## 6. 验收标准（主界面）

- [ ] 1024×768 投影、1366×768 笔记本、iPad 竖屏三种分辨率下都不出现滚动条（主界面一屏）
- [ ] 精灵立绘在 `#0A0E1A` 背景上无方角、无水印、无白边
- [ ] 三形态切换 900ms 内完成，切换后名称牌/星级同步更新
- [ ] 中端安卓机（骁龙 6 系）星点 + 漂浮 + 旋转光环同时开启时 ≥30fps
- [ ] 文字在深底上对比度 ≥4.5:1（金色文字仅 ≥18px 粗体）
- [ ] `prefers-reduced-motion` 下：关闭旋转/星点/粒子，保留静态光效
