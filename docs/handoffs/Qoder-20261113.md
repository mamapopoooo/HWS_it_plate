### 对 Codex 方案的两处修正

1. **IN-04 要拆成两条，破坏方式不同。** 方案写的是「缺席列写空/0」。实测：**缺席的是班级列时不会清空，而是 500 崩**（`students.class_id` 在 v1 建表里就是 `TEXT NOT NULL`，`importRoster` 把缺席班级算成 `null`），且整个 `db.transaction` 回滚，一条都写不进去；**缺席英文名列/课程列时才是静默清空**，而且 `users.name_en` 一起被清——数据损失面比方案描述的小一半，崩溃面比方案描述的多一个。补丁必须同时覆盖这两条路径。

2. **IN-02 的「非 JSON 回落空对象」不会把 500 变成假成功。** `src/api/roster.ts:19` 确实 `res.json().catch(() => ({}))`，但 `:20` 的 `if (!res.ok) throw` 仍会抛，教师端会红字报错（本轮 IN-04A 实测印证）。真正会假成功的是 **2xx + 非 JSON**（例如 API 前缀被 SPA 兜底页接管那次事故），那种情况下 `res.ok=true`、`data={}` 被当合法 `ImportResult` 返回。收口时按这个边界改，别按「所有非 JSON 都危险」改，否则会连带把 401 的处理也动了。

**IN-04（import-roster.js，语义已由用户定案）**
- 用户定案：**只更新表格里出现的列**，缺席列保留旧值；故意清空走单条编辑。
- UPDATE 按 `Object.prototype.hasOwnProperty` 判**键存在**（不是值真假）动态拼 SET；`undefined` 与缺席同等处理。
- 班级列缺席 → 保留原 `class_id`，顺带消除 IN-04A 的 NOT NULL 崩溃；新增学生缺必要信息 → 明确报错，不静默写 `grade=0`，也不用 `classId ?? ''` 插空串。
- dryRun 与实际写入**共用同一套列决策与校验**，输出「本次写入哪些列 / 跳过哪些列 / 无效或重复学号」。

**IN-05（migrate-roster.js）**
- 建索引前预检重复学号（`GROUP BY student_no HAVING COUNT(*)>1`），有重复**抛错中止且不 markApplied**。
- `CREATE UNIQUE INDEX` 不再 `catch {}`；`addCol` 改用 `PRAGMA table_info` 先判列存在、ALTER 真失败就抛（v10 补 users.name_en 同样在吞错）。
- 补一个**增量修复版本**：对已被错标 v9/v10 的库，用 PRAGMA 复核列与索引实况，缺约束的库在预检通过后补建。**版本号不抢，等 Codex 指定。**
- 补充发现（同一条根因）：全仓未见 `PRAGMA foreign_keys = ON`，better-sqlite3 默认 **OFF** → `class_id=''`、删班级留孤儿学生这类脏值不会被外键拦住。是否本轮开启属跨模块决策（会影响 `roster.js` 级联删除的既有假设），交 Codex 定。

**IN-06（roster.js `/bulk` action=move + 单条编辑）**
- 转班在同一事务内同时更新 `students` 的 `class_id` 与 `grade`，再同步 `users`；目标班级推导不出年级时**不猜测、不部分提交**（方案 §5 原文口径）。
