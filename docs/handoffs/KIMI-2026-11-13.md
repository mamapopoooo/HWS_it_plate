## KM-06 契约摘要

- **实例映射：** start 只接收本人 `player_pets.id`，再以 `template_id/level/awakening_level` 创建核心 fighter；核心 `petId` 始终是模板 ID，实例 ID 在会话另存。
- **调用方式：** `resolveSkill/endTurn` 原地修改 fighter，技能返回值只是事件数组。配置统一注入 `{tiers,trigrams,pets,economy,skillEffects}`，AI 和 RNG 均由服务端持有。
- **前置校验：** 核心不验证技能归属、冷却或战斗状态，未知技能还会回退首个技能；会话层必须先拒绝非法/冷却技能，且这些请求不得修改状态或消耗 RNG。
- **action 顺序：** 玩家技能→判胜→未终结才 AI 选技/技能→再判胜→未终结才 player/enemy `endTurn` 并 turn+1；终结后不再执行 AI、回合递减或奖励。
- **重放：** 同 battleId/actionId/请求体返回缓存响应，不同请求体 409；重放检查先于已结束拒绝，不推进 RNG、不重复落库。第一阶段只承诺同进程。
- **状态：** 内部会话与公开快照分离。fighter 的 HP、攻击、防御、盾、增益和完整 skills 冷却字段均须保留；rng 函数、Map 重放缓存、ownerId 和内部 log 不进入公开序列化。GET state 无副作用，建议 events 为空以避免刷新重放特效。
- **RNG：** 伤害技能先抽闪避，命中后才抽暴击；AI 选技抽一次。非法请求、GET、重放和 endTurn 不抽。Math.random 不能跨重启恢复；未来持久化须另存 PRNG 状态或固定算法版本的 seed+drawCount。
- **事件：** 玩家事件先于 AI；伤害内部为护盾吸收→hit/crit→可选 ko。`side` 是行动方而非目标方，shield 同时用于吸收和获得，页面不能统一按“自己获得护盾”解释。
- **未实现语义：** DOT 和 stun 状态仍不存在，不得在序列化中虚构；完整伪代码、RNG 分支次数、传输字段和路由测试清单见 KIMI REPORT 的 KM-06 节。
