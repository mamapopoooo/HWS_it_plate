## 3. 工作区隔离规范（所有 Agent 必须执行）

### 开始任务前

在自己的目录执行并记录：
```powershell
Get-Location
git rev-parse --show-toplevel
git branch --show-current
git status --short
git worktree list
```
确认目录、分支、任务一致；工作区有不属于自己的改动时不清理、不暂存、不覆盖，先报告归属不明的文件。
只使用独立 clone 或独立 worktree；禁止多个 Agent 共享同一工作目录，即使编辑不同文件也不行。

建议映射（示意路径，先检查实际 worktree，禁止机械重建）：
| 角色 | 分支 | 独立目录 |
|---|---|---|
| Codex | dev-codex-integration-* | ../pet-garden-codex |
| GPT-ART | dev-gpt-art | ../pet-garden-gpt-art |
| DSH | dev-dsh | ../pet-garden-dsh |
| KIMI | dev-kimi | ../pet-garden-kimi |
| Qoder | dev-qoder | ../pet-garden-qoder |
| CODEX-CONTROL | dev-codex-control-integration | ../pet-garden-control-docs |

已有分支用 git worktree add <目录> <分支>；新分支用 git worktree add -b <新分支> <目录> <已核实基线>。
不能把一个已检出的分支再绑定第二个 worktree；同一角色多个并发聊天也必须使用不同目录和子任务分支。

### 修改与提交

1. 只在自己目录和自己的任务分支改动；不在 main/dev 开发，不替别人切分支，不修改其他 worktree。
2. 不执行覆盖他人改动的 reset --hard、clean -fd、checkout/restore 全目录、自动 stash/pop；不 force push，不重写已发布共享历史。
3. 先确定本批文件清单。跨所有权先在自己的交接文档登记“拟改文件/原因/依赖”，由 Codex 确认接棒或统一实现；不要两个人同时改同一个共享文件。
4. git add 使用明确路径；提交前看 git diff 与 git diff --cached，确认无他人文件、真实名单、数据库、凭据和生成缓存。
5. 每个 Agent 单独安装依赖，不能互用可写 node_modules/dist；本地 .env、SQLite 文件与上传目录也必须独立。SQLite 测试只用虚构数据与临时库，不能指向生产或其他 Agent 的库。
6. 每个开发服务使用不同端口，并记录自己启动的 PID；只停止自己的进程，禁止按端口猜测后批量杀进程。
7. fetch 只更新远端引用，不会把他人的未提交文件拉过来。合并前由 Codex 指定基线 SHA；自己的树干净后再同步，不在脏树上 pull/rebase。
8. 各角色只推自己的分支。最终由 Codex 在整合分支合并，运行回归后再进入发布流程；本次不解除生产冻结。
9. worktree 共享 Git 对象与 refs，不等于运行资源隔离；独立数据库/端口/构建目录是额外硬要求。

### 交接格式与冲突

每个角色独写 docs/handoffs/<角色>-<日期>.md，避免多人改同一总表。至少包含：
```text
角色 / 任务号：
基线 SHA / 分支 / worktree：
本批拥有文件：
提交 SHA：
完成项与证据：
执行过的检查、结果、实际测试数：
未验证事项与阻塞：
给其他角色的依赖、需接棒文件：
是否涉及生产：否（当前冻结）
```
出现冲突先停止该文件写入、记录双方提交，由 Codex 三方比对。禁止用 ours/theirs 整文件覆盖跳过语义核对。
角色更新交接清单不等于已自动通知其他聊天；用户复制下面提示词后才启动对应工作。
